Antes de começar

Por que servidor dedicado — e o que este guia assume.

O SSX Desk roda como um processo Node único e contínuo, num container Docker. Isso não é preferência: três recursos só funcionam de verdade com um processo que não é reciclado — WhatsApp via Baileys (conexão WebSocket contínua), transcrição de áudio (Whisper local) e busca semântica (embeddings locais). Os três carregam modelo ou seguram conexão em memória, e nenhum sobrevive a um ambiente que desliga o processo entre requisições.

i

Este guia assume um servidor Ubuntu 22.04/24.04 LTS (VPS ou dedicado), que é o mesmo alvo Linux x64 pra qual os binários nativos do projeto (sharp, onnxruntime-node) já são otimizados no next.config.ts. Outra distro/arquitetura (ex: ARM) funciona, mas os comandos de instalação de pacote mudam.

iO que você vai precisar ter em mãos

  • Acesso root/sudo ao servidor
  • Um domínio próprio apontando pro IP do servidor (obrigatório — Web Push só funciona em HTTPS)
  • Backup/dump do banco de dados atual, se for migrar dados existentes
  • As credenciais atuais: GROQ_API_KEY, chaves VAPID, webhook do Bitrix24 (se usar)
!

O schema (schema_postgres.sql) começa com DROP TABLE ... CASCADE. Só rode contra um banco novo/vazio — nunca contra um banco com dados reais.

Sistema operacional & Node.js

Pacotes de sistema e Node na versão exigida pelo Next.js 15.Ubuntu 22.04/24.04

1Atualizar o sistema e instalar utilitários base

sudo apt update && sudo apt upgrade -y sudo apt install -y curl git build-essential ca-certificates gnupg

2Instalar o Node.js (20 LTS — exigido: ^18.18 / ^19.8 / >=20)

# NodeSource — instala Node 20 LTS + npm curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash - sudo apt install -y nodejs # conferir versões node -v npm -v

3Gerenciador de processo (mantém o Next.js no ar)

sudo npm install -g pm2
✓

Não precisa instalar ffmpeg separadamente — o pacote ffmpeg-static baixa o próprio binário durante o npm install do projeto (capítulo 04).

PostgreSQL

Instalação, criação do banco, schema e migrations — sem extensões especiais.

1Instalar o PostgreSQL

sudo apt install -y postgresql postgresql-contrib sudo systemctl enable postgresql --now

2Criar usuário e banco do sistema

sudo -u postgres psql -c "CREATE USER ssxdesk WITH PASSWORD 'TROQUE_ESTA_SENHA';" sudo -u postgres psql -c "CREATE DATABASE ssxdesk OWNER ssxdesk;"
i

Nenhuma extensão do Postgres é necessária — nem pgvector nem pgcrypto/uuid-ossp. UUIDs são gerados via md5(random()...) e a similaridade de embedding é calculada em JavaScript (ver comentário em migrations/ai_embeddings.sql).

3Aplicar o schema base (fonte de verdade)

# dentro da pasta do projeto (ver capítulo 04) psql "postgres://ssxdesk:TROQUE_ESTA_SENHA@localhost:5432/ssxdesk" -f schema_postgres.sql

4Aplicar as migrations, em ordem

Não existe runner automático — cada arquivo de migrations/*.sql é aplicado uma vez, manualmente. São 60+ arquivos hoje; rodar todos em ordem alfabética/cronológica cobre o estado atual:

for f in migrations/*.sql; do echo "Aplicando $f..." psql "postgres://ssxdesk:TROQUE_ESTA_SENHA@localhost:5432/ssxdesk" -f "$f" || break done
!

Confira o resultado de cada arquivo antes de seguir pro próximo (o script acima já para no primeiro erro com || break). Nunca edite uma migration já aplicada — crie uma nova em vez disso.

Projeto & dependências

Clonar o repositório e instalar as dependências, incluindo os módulos nativos.

1Clonar o projeto

cd /opt sudo git clone <URL_DO_REPOSITORIO> ssx-desk sudo chown -R $USER:$USER ssx-desk cd ssx-desk

2Instalar as dependências

npm install

Isso já resolve os módulos nativos que o projeto precisa — nenhum é instalado à parte no sistema operacional:

sharp
Processamento de imagem (avatares, fotos de contato)
onnxruntime-node
Motor de inferência do Whisper e dos embeddings
bufferutil / utf-8-validate
Aceleração WebSocket (Baileys / ws)
ffmpeg-static
Binário próprio do ffmpeg (decodifica áudio)
✓

Em Ubuntu 22.04/24.04 x64 (o alvo já otimizado no next.config.ts), esses módulos baixam binário pré-compilado — não deve ser preciso compilar nada localmente.

Modelos de IA locais

Whisper (transcrição) e o modelo de embedding (busca semântica) — nada disso vem no npm install.

Os dois modelos são baixados do Hugging Face Hub na primeira vez que a funcionalidade correspondente é usada, não durante o deploy. Nada a "instalar" aqui além de garantir os pré-requisitos abaixo antes de ligar as flags do capítulo 06:

  • Acesso de saída à internet liberado pro Hugging Face Hub (huggingface.co / CDN)
  • Espaço em disco livre: ~150MB pro Whisper (Xenova/whisper-base) + espaço menor pro modelo de embedding (Xenova/paraphrase-multilingual-MiniLM-L12-v2)
  • Permissão de escrita no diretório de cache do processo (padrão da biblioteca @huggingface/transformers)

1Testar o download antecipadamente (opcional)

Pra não deixar o primeiro cliente esperando o download na hora, pode-se "esquentar" o cache manualmente após o primeiro pm2 start (capítulo 07): dispare uma transcrição de teste e uma pergunta ao Agente de IA assim que o serviço subir, antes de anunciar o servidor como pronto.

i

É por isso que essas duas flags (ENABLE_AUDIO_TRANSCRIPTION e ENABLE_AI_EMBEDDINGS) vêm desligadas por padrão: exigem disco pro cache do modelo e CPU dedicada. Num servidor próprio como este, ligar as duas é seguro — no container, o cache precisa apontar pro volume (HF_HOME=/data/models), senão cada restart rebaixa o modelo inteiro.

Build & processo persistente

O processo Node precisa ficar sempre no ar — e ser um só.

1Build de produção

# roda check:encoding automaticamente antes (script prebuild) npm run build

2Subir com PM2

pm2 start npm --name "ssx-desk" -- start pm2 save pm2 startup # segue a instrução impressa pra registrar no boot do SO
i

É esse processo único e contínuo que sustenta o sistema: a conexão WebSocket do WhatsApp (Baileys) e os schedulers internos (fila de embeddings, alerta de hotfix vencido, detector de insatisfação) rodam dentro dele via setInterval — registrados em instrumentation-node.ts na subida do processo. Único mesmo: dois processos contra o mesmo banco duplicam a mensagem automática enviada ao cliente e brigam pela sessão do WhatsApp.

3Comandos úteis do dia a dia

pm2 logs ssx-desk # acompanhar logs em tempo real pm2 restart ssx-desk # reiniciar (ex: depois de mudar o .env) pm2 status # ver se está no ar

Domínio, HTTPS & proxy reverso

HTTPS é obrigatório — Web Push e Service Worker não funcionam em HTTP fora de localhost.

1Instalar Nginx

sudo apt install -y nginx

2Configurar o site (proxy pra porta 3000)

sudo nano /etc/nginx/sites-available/ssx-desk server { listen 80; server_name SEU_DOMINIO.com.br; location / { proxy_pass http://localhost:3000; proxy_http_version 1.1; proxy_set_header Upgrade $http_upgrade; proxy_set_header Connection 'upgrade'; proxy_set_header Host $host; proxy_set_header X-Real-IP $remote_addr; proxy_cache_bypass $http_upgrade; } }
sudo ln -s /etc/nginx/sites-available/ssx-desk /etc/nginx/sites-enabled/ sudo nginx -t sudo systemctl reload nginx

3Certificado HTTPS (Let's Encrypt)

sudo apt install -y certbot python3-certbot-nginx sudo certbot --nginx -d SEU_DOMINIO.com.br
✓

O proxy_set_header Upgrade acima é o que permite o SSE (/api/chats/stream) funcionar corretamente atrás do Nginx — não remova.

Rede & contas externas

O que o firewall precisa liberar e o que precisa estar pronto do lado de fora.

1Saída (outbound) liberada para

  • Servidores do WhatsApp (Baileys — WebSocket)
  • api.groq.com (Agente de IA)
  • Hugging Face Hub (download dos modelos locais)
  • Bitrix24, se for usar a sincronização (BITRIX24_WEBHOOK_URL)
  • Serviços de push do navegador do cliente (FCM/APNs/Mozilla, conforme o browser)
  • use.typekit.net (fonte da marca, Adobe Fonts)

2Entrada (inbound) liberada para

  • Portas 80/443 (HTTPS via Nginx)
  • /api/whatsapp/webhook roteável publicamente, se for usar o WhatsApp oficial (Meta Cloud API)

3Contas/credenciais a providenciar

Groq
Chave de API de produção — decidir se reaproveita a atual ou cria uma nova (cota é por conta)
VAPID
Par de chaves gerado no capítulo 06
Bitrix24
Webhook de entrada, se for sincronizar empresas/equipe
Meta for Developers
App configurado, só se for usar WhatsApp oficial (Cloud API)
i

Não é preciso provisionar S3/object storage: anexos de chat são gravados como data: URL direto no Postgres (chat_messages.metadata). Nenhum serviço de armazenamento externo entra nesta lista.

Checklist final

Confirmação ponta a ponta antes de anunciar o servidor como pronto.

  • Node.js 20 LTS instalado (node -v dentro da faixa exigida)
  • PostgreSQL no ar, schema aplicado, todas as migrations rodadas em ordem
  • npm install concluído sem erro nos módulos nativos (sharp, onnxruntime-node, bufferutil, utf-8-validate)
  • .env completo (tabela do capítulo 06), incluindo ENABLE_AUDIO_TRANSCRIPTION e ENABLE_AI_EMBEDDINGS
  • npm run build concluído sem erro
  • PM2 rodando o processo, com pm2 startup registrado (sobrevive a reboot)
  • Domínio resolvendo pro servidor, HTTPS válido (cadeado no navegador)
  • Login funcionando (/login)
  • WhatsApp conectando (QR code em Configurações, se for usar Baileys)
  • Notificação push chegando (testar em Configurações → Notificações)
  • Transcrição de áudio funcionando num chat de teste (baixa o modelo na 1ª vez)
  • Agente de IA respondendo, inclusive com semantic_search (pergunta parafraseada encontra chamado antigo)
✓

Com tudo isso marcado, o servidor cobre os três recursos que exigem processo contínuo: WhatsApp persistente, transcrição de áudio e busca semântica.
