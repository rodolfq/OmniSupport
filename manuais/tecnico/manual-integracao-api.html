Visão geral

Uma API própria, independente do login do portal.

A API de integração é uma camada separada do portal — não usa o cookie de sessão que um analista usa ao logar. Ela existe pra que outro sistema (um CRM, um ERP, um portal do cliente) converse diretamente com os dados do SSX Desk: ler chamados e conversas, cadastrar funcionários, atualizar o status de um atendimento — tudo via requisição HTTP simples, autenticada por uma chave de API própria.

⚠

Chamadas sempre partem do backend da plataforma parceira — nunca do navegador do usuário final. A chave de API dá acesso amplo aos dados; colocá-la em código que roda no navegador expõe essa chave pra qualquer pessoa que abrir o Developer Tools.

iOs quatro recursos disponíveis

🏢Empresas

Consultar o cadastro de clientes e atualizar dados (nome, indústria, telefone, "em treinamento").

👤Funcionários

Listar, cadastrar, atualizar e desativar contatos de uma empresa-cliente.

🎫Chamados

Consultar, abrir novos chamados e atualizar status/prioridade/responsável.

💬Conversas

Consultar o histórico de conversas de chat e WhatsApp, com mensagens e anexos.

iiEndereço base

Toda rota começa com /api/integrations/v1/, no mesmo domínio onde o portal está publicado — não existe um subdomínio separado pra API.

# exemplo — troque pelo domínio real do seu SSX Desk https://suporte.suaempresa.com.br/api/integrations/v1/ping

Autenticação & escopos

Uma chave por integração, com só as permissões que ela precisa.

1Gerar a chave

  1. No portal: Configurações → Integrações (exige a permissão "Integrações" ou ser Administrador).
  2. Clique em Nova Chave, dê um nome que identifique a integração (ex.: "CRM Comercial") e marque só os escopos que ela vai usar de verdade.
  3. A chave completa (formato ssx_...) aparece uma única vez, na hora da criação — copie e guarde num cofre de segredos da plataforma parceira. Se for perdida, a única saída é gerar outra e revogar a antiga.
!

Não existe recuperação de chave perdida. O banco guarda só o hash dela (mesmo padrão de senha do sistema) — nem o time de suporte consegue ver a chave de novo depois de fechar a tela de criação.

2Enviar a chave nas requisições

Em qualquer um dos dois formatos abaixo — os dois funcionam de forma idêntica:

Authorization: Bearer ssx_a1b2c3d4e5f6... # — ou — x-api-key: ssx_a1b2c3d4e5f6...

3Escopos disponíveis

Cada chave só faz o que os escopos marcados nela permitem — uma chave sem tickets:write, por exemplo, nunca consegue abrir ou alterar um chamado, mesmo que o endpoint exista.

EscopoLibera
companies:readListar e consultar empresas.
companies:writeAtualizar dados de empresa — já inclui a leitura.
employees:readListar e consultar funcionários.
employees:writeCadastrar, atualizar e desativar funcionários.
tickets:readListar e consultar chamados (com mensagens visíveis ao cliente).
tickets:writeAbrir chamados novos e atualizar status/prioridade/classificação/responsável.
conversations:readListar e consultar conversas de chat/WhatsApp.
i

Chave criada antes desta versão com o escopo employees:read continua conseguindo ler empresas por compatibilidade — mas para chaves novas, use companies:read, que é o nome certo pra essa permissão.

4Testar antes de integrar de verdade

Use o endpoint de teste — não lê nenhum dado de negócio, só confirma que a chave está válida e devolve os escopos dela:

GET/api/integrations/v1/pingsem escopo
Resposta 200
{ "data": { "ok": true, "keyName": "CRM Comercial", "scopes": ["tickets:read", "tickets:write"] } }

Convenções da API

Toda rota segue o mesmo formato — aprenda uma vez, use em todas.

1Formato da resposta

Sucesso sempre vem dentro de data. Listagem paginada também traz meta:

{ "data": [ /* ... */ ], "meta": { "limit": 100, "offset": 0, "total": 342, "hasMore": true } }

Pra avançar, repita a chamada aumentando offset em limit — pare quando hasMore vier false. O máximo de limit é 500 por página; pedir mais que isso é silenciosamente limitado a 500.

2Sincronização incremental

Chamados e conversas aceitam ?updatedSince= (data/hora ISO 8601) pra trazer só o que mudou depois de uma sincronização anterior — evita reler a base inteira a cada rodada de sincronismo.

GET /api/integrations/v1/tickets?updatedSince=2026-08-01T00:00:00Z
✓

Guarde o horário em que a sincronização terminou (não em que começou) e use esse valor como updatedSince na próxima rodada — assim nenhuma mudança fica de fora, mesmo que a sincronização demore alguns minutos.

3Formato de erro

{ "error": "Esta chave de API não tem o escopo necessário: tickets:write", "code": "FORBIDDEN_SCOPE" }
StatusCódigoQuando acontece
401UNAUTHORIZEDChave ausente, inválida ou revogada.
403FORBIDDEN_SCOPEChave válida, mas sem o escopo exigido por esse endpoint.
400VALIDATION_ERRORCampo obrigatório ausente, formato inválido, ou referência (categoryId, companyId...) inexistente.
404NOT_FOUNDO id informado não existe.
409CONFLICTViolação de unicidade — ex.: e-mail de funcionário já cadastrado.
429RATE_LIMITEDMais de 120 requisições/minuto para essa chave.
500INTERNAL_ERRORFalha inesperada do lado do servidor — não é um erro de uso da API.

4Limite de requisições

Toda resposta autenticada traz os headers abaixo, pra sua integração acompanhar a própria cota sem precisar levar um 429 primeiro:

X-RateLimit-Limit: 120 X-RateLimit-Remaining: 117 X-RateLimit-Reset: 1786994325 // epoch em segundos

O limite é 120 requisições por minuto, por chave. Passou disso, a resposta vem com status 429 até a janela seguinte começar.

i

Nenhuma anotação interna aparece por esta API: mensagem marcada como "nota interna" num chamado, ou "aviso de bastidores" numa conversa (ex.: transferência entre atendentes) nunca é devolvida — só o que o próprio cliente também veria.

Empresas

Cadastro de clientes — resolva o companyId aqui antes de usar nos outros recursos.

GET/api/integrations/v1/companiescompanies:read

Sem id, devolve todas as empresas. Com id, devolve só uma — incluindo o resumo de avaliação interna (nota do relacionamento, nunca visível ao próprio cliente).

ParâmetroOndeDescrição
idqueryuuid — retorna só essa empresa.
Resposta 200 (resumida)
{ "data": [{ "id": "56f9...", "name": "Empresa Matriz Ltda", "industry": "Tecnologia", "isInTraining": false, "evaluation": { "count": 3, "overallAverage": 4.2, "latestTag": "technical" } }] }
PUT/api/integrations/v1/companies?id=companies:write

Atualização parcial — envie só os campos que quer mudar. Inclui o indicador "cliente em treinamento", que mostra um aviso pra equipe interna no chat. As notas de avaliação em si não são editáveis por esta API, só pelo portal.

CampoOndeDescrição
idqueryobrigatório
namebodyNovo nome.
industrybodyNovo ramo/indústria.
phonebodyNovo telefone.
isInTrainingbodyboolean.
✓

Fluxo recomendado pra cadastrar um funcionário: primeiro GET /companies pra achar (ou confirmar) o id certo, depois use esse id como companyId em POST /employees.

Funcionários

Contatos de uma empresa-cliente — nunca ganham acesso de login pelo cadastro via API.

GET/api/integrations/v1/employeesemployees:read
ParâmetroOndeDescrição
idqueryRetorna só esse funcionário (ativo ou não).
companyIdqueryFiltra por empresa.
emailqueryFiltra por e-mail exato.
includeInactivequery"1" pra incluir quem foi desativado. Padrão: só ativos.
limit / offsetqueryPaginação — padrão 100, máximo 500.
POST/api/integrations/v1/employeesemployees:write
CampoOndeDescrição
namebodyobrigatório
emailbodyobrigatório — único no sistema
phonebodyOpcional.
companyIdbodyEmpresa vinculada.
rolebody"Funcionário" (padrão) ou "Cliente".
!

O registro nasce sem senha — é só sincronismo de dado, não cria acesso de login ao portal. Nunca é possível criar via esta API alguém com papel Administrador/Equipe/Time Interno.

PUT/api/integrations/v1/employees?id=employees:write

Atualização parcial. Envie isActive: true pra reativar um funcionário desativado.

DELETE/api/integrations/v1/employees?id=employees:write

novo

Desativação suave — o registro nunca é apagado de verdade, porque chamados e conversas antigas continuam apontando pra ele. A partir daí, some das listagens padrão (a menos que peça includeInactive=1). Reverter é um PUT com isActive: true.

Chamados

Consultar, abrir e movimentar chamados de suporte — com as mesmas automações do portal.

GET/api/integrations/v1/ticketstickets:read

Com id, inclui as mensagens visíveis ao cliente. Sem id, aceita companyId, status e updatedSince como filtro.

Resposta 200 (item da lista)
{ "id": "2948...", "ticketNumber": 23, "title": "Impressora não liga", "status": "Novo", "subStatus": null, "priority": "Média", "categoryId": "a1b2...", "tags": ["hardware"], "companyId": "56f9...", "assigneeId": null, "createdAt": "...", "updatedAt": "..." }
POST/api/integrations/v1/ticketstickets:write

novo

Abre um chamado com status inicial "Novo". Dispara a mesma automação de "novo chamado" configurada em Configurações — a equipe é avisada igual a um chamado aberto pelo próprio portal.

CampoOndeDescrição
titlebodyobrigatório
descriptionbodyobrigatório
companyIdbodyobrigatório
customerIdbodyContato específico que abriu.
prioritybodyBaixa (padrão) / Média / Alta / Urgente.
categoryId / requestTypeId / productIdbodyClassificação (listas configuráveis).
tagsbodyArray de marcadores livres.
PATCH/api/integrations/v1/tickets?id=tickets:write

novo

Atualização parcial de status, prioridade, classificação ou responsável. Dispara a mesma automação do portal — troca de status pode enviar e-mail/WhatsApp configurado pra esse status, atribuir responsável notifica por e-mail.

CampoOndeDescrição
statusbodyPrecisa ser um rótulo já cadastrado em Configurações.
prioritybodyBaixa / Média / Alta / Urgente.
categoryId / requestTypeId / productIdbodyNova classificação.
tagsbodySubstitui os marcadores.
assigneeIdbodyNovo responsável.
⚠

Status é livre em Configurações — a API valida contra a lista real antes de gravar. Mandar um status que não existe (erro de digitação, ou uma automação da plataforma parceira desatualizada) devolve 400 VALIDATION_ERROR, sem gravar nada.

Conversas

Histórico de chat ao vivo e WhatsApp — só leitura.

GET/api/integrations/v1/conversationsconversations:read

Com id, devolve a conversa inteira com as mensagens do cliente e da equipe (nunca as anotações internas — ver capítulo 03). Sem id, aceita companyId, customerId, status e updatedSince.

ParâmetroOndeDescrição
idqueryRetorna essa conversa + mensagens.
companyIdqueryFiltra pela empresa do cliente.
customerIdqueryFiltra por cliente.
statusquerywaiting / active / closed.
updatedSincequeryISO 8601 — sincronização incremental.
Mensagem, dentro de uma conversa específica
{ "id": "...", "senderName": "Jean", "text": "Bom dia!", "type": "text", "attachments": [], "createdAt": "2026-08-17T12:00:00.000Z" }
i

queueId na conversa identifica a fila/canal de onde ela veio — útil pra separar atendimentos por instância de WhatsApp quando a operação usa mais de um número.

Checklist & boas práticas

Confira antes de ligar a integração em produção.

  • Chave criada com só os escopos necessários — nunca marque tudo "por garantia".
  • GET /ping respondeu 200 com os escopos esperados.
  • A plataforma parceira trata 429 (limite de requisições) com espera e nova tentativa, em vez de descartar a chamada.
  • Toda listagem pagina de verdade (usa hasMore/offset) — nenhuma integração assume que a primeira página é tudo.
  • Sincronização recorrente usa updatedSince, não reprocessa a base inteira a cada rodada.
  • Erros 400/404/409 são tratados como respostas normais da API (o corpo explica o motivo em error), não como falha de conexão.
  • A chave fica guardada num cofre de segredos do lado da plataforma parceira — nunca em código versionado.
  • Chamada feita sempre do backend da plataforma parceira, nunca do navegador do usuário final.

iSe algo parar de funcionar

401 Unauthorized
A chave foi revogada ou excluída em Configurações → Integrações. Confirme lá se ela ainda está "Ativa".
403 Forbidden_Scope
Falta um escopo na chave. Peça pra quem administra o sistema adicionar o escopo — não dá pra editar escopo de uma chave existente, é preciso gerar outra.
✓

Revogar uma chave (em vez de excluir) corta o acesso na hora, mas mantém o histórico de uso — dá pra reativar depois se for engano. Excluir é definitivo.
